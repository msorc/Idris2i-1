## How the compiler builds itself

```text
IDRIS2I_1_BOOT (an installed Idris2i-1, with its own prelude/base/network...)
   |  idris2i-1 --build idris2i-1.ipkg   (IDRIS2I_1_CG=refc: Idris -> C -> cc)
   v
build/exec/idris2i-1             launcher script (bootstrap/idris2i-1-refc.sh)
build/exec/idris2i-1_app/idris2i-1  the binary, linked with support/c of the tree
   |  make libs: build/exec/idris2i-1 --build libs/<lib>/<lib>.ipkg
   v
libs/<lib>/build/ttc/<ttcVersion>/...   the libraries, as TTC files
   |  make testenv
   v
build/env/idris2i-1-0.8.0/<lib>-0.8.0 -> libs/<lib>/build/ttc   (symlinks)
build/env/idris2i-1-0.8.0/{lib,support}                         (installed support)
```

- `idris2i-1.ipkg` depends on `network`, so the boot compiler needs `prelude`,
  `base`, `linear` and `network` installed under its own prefix.
- `src/IdrisPaths.idr` is generated by `make` (gitignored): it holds the
  version, the commit (`git rev-parse --short=9 HEAD`) and the installation
  prefix (`PREFIX`). A bare `idris2i-1 --build idris2i-1.ipkg` in a fresh checkout
  fails without it; run `make src/IdrisPaths.idr` first.
- With RefC the compiler binary links the C support library of the tree
  (`support/c`), and its C is compiled with that library's headers, so a
  change in `support/c` is seen by the next `make idris2i-1-exec`. The RefC
  runtime (`support/refc`) used to compile the compiler stays the one of
  `IDRIS2I_1_BOOT`, because it must match the C that the boot compiler writes.
  Programs compiled by the *new* compiler in the tests use the runtime of the
  tree, which `make test` installs in `build/env`.
- `idris2i-1 --build` skips compiling an executable whose stamp
  (`build/exec/idris2i-1.stamp`) says nothing it is made from changed: it then
  prints `The executable ... is up to date, not compiling it again`.
  `--log package.stamp:5` says why it did compile.
- TTC files record the compiler version, and a TTC from another version is
  rebuilt. The version includes the commit, not uncommitted edits: see
  `traps.md`, "Stale library TTCs".

## Targets

| Target | What it does |
|---|---|
| `make` / `make all` | `build/exec/idris2i-1`, then `make libs` |
| `make idris2i-1-exec` | the compiler only |
| `make libs` | all libraries with `build/exec/idris2i-1` (prelude, base first, then the rest, `LIBS_PARALLEL` at a time with RefC) |
| `make prelude`, `base`, `linear`, `contrib`, `network`, `test-lib`, `papers`, `http`, `tls`, `http-tls` | one library and those it depends on |
| `make support` | the C support libraries in `support/` (rebuilds what changed) |
| `make testenv` | installs the support libraries in `build/env`, links the libraries there, builds the test runner `tests/build/exec/runtests` |
| `make test`, `make retest` | the golden tests (see `tests.md`); neither rebuilds the compiler nor the libraries |
| `make test-installed` | the tests with `$PREFIX/bin/idris2i-1` |
| `make api-check` / `make api-snapshots` | compare / rewrite `libs/api/<lib>.api` from `idris2i-1 --dump-api` (needs built libraries) |
| `make libdocs` | HTML docs of the libraries |
| `make clean-libs` | removes `libs/*/build`: every library is rebuilt next time (and `build/env` points at nothing until then) |
| `make clean`, `make distclean` | everything the build made (`distclean` also every `.ttc`, `.ttm`, `.ibc` in the tree) |
| `make install` | compiler, support and libraries under `PREFIX`: only when the task says so |
| `make bootstrap-c`, `bootstrap`, `bootstrap-racket`, `bootstrap-test` | see Bootstrapping |

## Variables

Set them on the command line (`make IDRIS2I_1_JOBS=4`), in the environment
where `make help` says so, or in `custom.mk` (gitignored, read by
`config.mk`) to keep them.

| Variable | Default | Meaning |
|---|---|---|
| `PREFIX` | `$HOME/.idris2i-1` | where `make install` puts things; also baked into the compiler as its prefix |
| `IDRIS2I_1_BOOT` | `idris2i-1` | the compiler that builds the compiler; may carry options (`"idris2i-1 -Werror"`, as CI does) |
| `IDRIS2I_1_CG` | `refc` | the back end the compiler is *built* with (`refc`, `chez`, `racket`); it does not change the default back end of the result, which is RefC |
| `IDRIS2I_1_JOBS` | processors, up to 16 | modules checked in parallel (`IDRIS2I_1_BUILD_JOBS` of the compiler); 1 builds one after the other |
| `IDRIS2I_1_CC_JOBS` | processors, up to 16 | environment: C compilers that compile the parts of a big RefC program (the compiler) in parallel |
| `LIBS_PARALLEL` | 3 with RefC, else 1 | libraries built at the same time, each with half of `IDRIS2I_1_JOBS` |
| `LIBS_INC_CGS` | empty, `chez` for a compiler on Chez | back ends that also compile the libraries module by module for incremental builds |
| `LTO` | 0 | 1 compiles the compiler's C with `-O2 -flto=auto`: about 4% faster compiler, about twice the C build time |
| `CFLAGS`, `IDRIS2I_1_CFLAGS` | `-O1` | C flags for the compiler's own C, in place of the `LTO` choice |
| `BOOT_CFLAGS`, `BOOT_JOBS`, `BOOT_PARTS` | `-O1`, processors (up to 16, one per 1.5 GB free), 16 | environment: the first stage of `make bootstrap-c` |
| `API_LIBS` | `prelude base contrib http tls http-tls` | libraries that `api-check` and `api-snapshots` compare |
| `IDRIS2I_1_TLS` | 1 when `pkg-config` finds OpenSSL 3 | build, test and install `tls` and `http-tls` |
| `only=`, `except=` | | limit the tests |
| `threads=` | processors | test threads (`tests/Makefile`) |
| `INTERACTIVE=` | `--interactive` | pass `INTERACTIVE=''` always (see `tests.md`) |

On a machine shared with other agents, lower the parallelism:

```sh
make idris2i-1-exec IDRIS2I_1_BOOT=$HOME/.idris2i-1/bin/idris2i-1 IDRIS2I_1_JOBS=4 IDRIS2I_1_CC_JOBS=4
```

## Running the compiler that was just built

`build/exec/idris2i-1` works from any directory, but its prefix is `PREFIX`
as it was at build time, so on its own it loads the installed libraries,
which can be older or of another TTC version. Give it the test prefix:

```sh
make testenv
IDRIS2I_1_PREFIX=$PWD/build/env build/exec/idris2i-1 --paths   # check what it loads
IDRIS2I_1_PREFIX=$PWD/build/env build/exec/idris2i-1 --exec main Foo.idr
```

`IDRIS2I_1_PREFIX` is also where `--install` writes: set it to a scratch
directory before any `--install` from a compiler that is not installed, or
it writes into `~/.idris2i-1`.

Check a build before trusting it: `build/exec/idris2i-1 --version` names the
commit the compiler was built from, and `build/exec/idris2i-1_app/idris2i-1`
should be an executable (`file` says ELF on Linux), not a copy of the
launcher script.

## Building in a separate tree

The checkout holds one `build/exec`, one set of `libs/*/build`, one
`build/env` and one `output` file per test. An agent that builds or tests
there while another one does gets the other's compiler, or a library
directory emptied under it (`make clean-libs`, a bootstrap). Work in a
worktree of your own, made from `devel`:

```sh
git worktree add -b fix/my-topic ../Idris2-wt/fix-my-topic devel
cd ../Idris2-wt/fix-my-topic
make IDRIS2I_1_BOOT=$HOME/.idris2i-1/bin/idris2i-1 IDRIS2I_1_JOBS=4 IDRIS2I_1_CC_JOBS=4
make test only=idris2i-1/basic INTERACTIVE='' threads=4 < /dev/null
```

- A new worktree has no TTC files: the first `make` checks all of the
  compiler and all libraries (several minutes).
- Check what it is based on (`git log -1 --oneline`, `git merge-base HEAD
  devel`). Worktrees that a tool creates for you may start from `main`,
  which is upstream and lacks most of this fork: a RefC build of it fails
  in ways that look like a broken checkout.
- Do not `make install` from a worktree. Everything else stays inside it.
- Only stop processes you started (by PID). `pkill -f idris2i-1` also kills
  other agents' builds.

## Bootstrapping

Needed only when there is no usable Idris2i-1 of this fork: a fresh machine,
or a boot compiler that cannot build `src/` any more. Normal work uses the
installed compiler as `IDRIS2I_1_BOOT`.

| Route | Needs | What it does |
|---|---|---|
| `make bootstrap-c` | C compiler, `make`, `xz`, GMP | compiles `bootstrap/idris2i-1_app/idris2i-1.c.xz` (generated by RefC) in `BOOT_PARTS` parts, builds the bootstrap libraries into `bootstrap-build/`, then `make clean-libs` and `make all` with that compiler (with `LTO=1` unless `LTO=0` is given) |
| `make bootstrap SCHEME=chez` | Chez Scheme with threads | the same from `bootstrap/idris2i-1_app/idris2i-1.ss` |
| `make bootstrap-racket` | Racket | the same from `idris2i-1.rkt` |
| `make bootstrap-test` | | `make test` with `IDRIS2I_1_PREFIX=bootstrap-build` |

All of them end with `make clean-libs` and a full `make all` in the tree:
never run one in a checkout that someone else is using. The result is in
`build/exec`; `make install` installs it. `bootstrap/update-c-bootstrap.sh
build/exec/idris2i-1.c` regenerates the C bootstrap file from the C of a
compiler built with RefC (only when the bootstrap itself has to move on).

## When the boot compiler is too old

If `src/` starts using something the installed compiler does not have (a
new primitive, syntax, a library function), the boot compiler cannot
check it. Build once with the old compiler from a version of `src/` it can
check, then use a copy of that result as the boot compiler. Do not point
`IDRIS2I_1_BOOT` at `build/exec/idris2i-1` itself: the build replaces that file
while it runs.

```sh
cp -a build/exec /path/to/scratch/boot-exec
make idris2i-1-exec IDRIS2I_1_BOOT=/path/to/scratch/boot-exec/idris2i-1
```

The copied compiler still looks for its libraries (`network` and its
dependencies) under its baked-in prefix, so they must be installed there
for its TTC version; export `IDRIS2I_1_PREFIX` to a prefix that has them if
they are not.
